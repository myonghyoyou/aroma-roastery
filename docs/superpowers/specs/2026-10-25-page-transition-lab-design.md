# 페이지 전환 실험실 (1단계: 시안 2·3)

근거: `reports/홈 페이지 전환 애니메이션 레퍼런스.md` (2026-10-25 수정판)

## 목적

홈·`/archive`·`/news` 사이 이동에 전환 애니메이션 시안을 붙여 실제 페이지에서 비교한다. 1단계는 시안 2(에스프레소 블라인드)와 시안 3(필드 연속)이고, 시안 3은 홈 WebGL 캔버스가 View Transition 스냅샷에 제대로 찍히는지를 검증하는 역할도 한다. 2단계에서 시안 1·4·5를 더한다.

## 범위

- 브랜치 `transition-lab`. main에는 그대로 합치지 않는다. 최종안이 정해지면 그 시안만 다시 옮긴다.
- 전환은 헤더·푸터에서 홈·아카이브·소식으로 가는 링크에 건다(`transitionTypes={['tx-nav']}`): 아카이브·소식 링크, 서브페이지의 로고와 `매장 정보`(`/#store`). 어느 방향이든 같은 시안이 같은 시간으로 재생된다(2026-10-25 결정). 브라우저 뒤로가기에는 타입이 없어 전환되지 않는다.

## 구조

- **전환 패널** (`src/components/lab/TransitionLab.tsx`, 루트 `layout.tsx`에 마운트): `?lab=1`로 켜고 `?lab=0`으로 끈다. 켜진 상태와 고른 시안은 localStorage에 둔다. 고른 시안은 `<html data-tx="2|3">`로 표시하고, 시안 CSS는 모두 이 속성 아래에만 건다. 속성이 없으면 모든 view transition 애니메이션을 끈다. 이때도 브라우저의 전환 절차 자체는 일어나므로 "끔"은 "애니메이션만 없는 상태"다.
- **React `<ViewTransition>`**: 홈 `page.tsx`에서 `<GrainStage>`를 바깥에서 감싸고, `SubPage`의 최상단을 감싼다. 둘 다 `tx-nav` 타입일 때 들어오면 `tx-in`, 떠나면 `tx-out` 클래스가 붙고 그 외는 `none`.
- **CSS** (`src/app/transition-lab.css`): 시안별 `::view-transition-*` 규칙, reduced-motion 대체.

## 시안 (2026-10-25: 처음 안보다 짧게)

- **2. 에스프레소 블라인드**: 화면 크기의 에스프레소 막이 0.25초(`power2.out`) 동안 짙어져 화면을 덮고, 덮인 순간 페이지가 바뀐 뒤 0.8초(`cubic-bezier(.4,0,0,1)`) 동안 위로 걷히며 새 페이지가 아래부터 드러난다. 막은 루트 레이아웃에 깔아 둔 화면 크기의 에스프레소 요소(`.tx-blind`, 모든 페이지 뒤에 있어 평소엔 안 보임)의 스냅샷이라 늘 화면 크기 그대로다. 처음에는 바탕(root) 스냅샷을 막으로 썼으나, React가 전환 중 `<html>`의 전환 이름을 `none`으로 바꾸고 root 그룹을 투명하게 만들어 막이 보이지 않았다(2026-10-25, 녹화와 react-dom 소스로 확인). 처음 안은 새 페이지 자체를 `clip-path`로 여는 방식이었으나, 홈은 떠났던 스크롤 위치로 되살아나므로 페이지 기준 경계는 화면 밖에서 움직일 수 있어 바꿨다.
- **3. 필드 연속** (2026-10-25 선택, 시간을 다시 줄임): 홈 `#field`와 서브페이지 `.sub-field`에 같은 이름(`grain-field`)을 줘서 0.3초 동안 잇는다. 콘텐츠는 위치 이동 없이, 떠나는 쪽은 0.2초에 사라지고 들어오는 쪽은 0.05초 뒤부터 0.5초에 걸쳐 나타난다(opacity만). 처음에는 `blur(6px) sepia(.45)`에서 선명해지게 했으나, 녹화 분석에서 화면 몇 배 크기의 스냅샷에 거는 블러가 떨어진 프레임을 14개에서 45개로 늘려 뺐다(2026-10-25). 헤더에는 이름을 주지 않는다. 헤더가 `position: absolute`라 푸터에서 누르면 화면 밖에서 날아 들어오기 때문이다.

## 접근성

`prefers-reduced-motion: reduce`이면 두 시안 모두 200ms opacity 페이드만 남긴다.

## 확인할 가정 (화면으로 확인)

1. `cacheComponents`의 Activity 숨김·되살림에서도 래퍼의 exit·enter가 발화하는가.
2. `preserveDrawingBuffer` 없는 WebGL 캔버스가 떠날 때 정지 화면으로 제대로 찍히는가(Chrome·Safari·Firefox).
3. 홈으로 들어올 때 엔진이 다시 만들어지는 동안 홈 캔버스가 잠깐 비어 보이지 않는가(시안 3에서 특히).

## 검증

자동 테스트는 없다. 빌드·lint 통과, 프로덕션 서버(`next build && next start`)에서 확인한다. dev 서버에서는 prefetch가 꺼져 공유 요소 전환이 재현되지 않으므로 쓰지 않는다.

## 결정 (2026-10-25)

시안 3(필드 연속)을 채택했다. 실험 장치(전환 패널, `?lab`, `data-tx`)와 시안 2(에스프레소 블라인드, `.tx-blind`)는 걷어 내고, 시안 3을 `src/app/page-transition.css`로 옮겨 항상 동작하게 했다. 시간은 위 시안 3 항목의 값(필드 0.3초, 나감 0.2초, 들어옴 0.05초 뒤 0.5초)이다. 2단계 시안(1·4·5)은 만들지 않았다.

함께 들어간 성능 수정: 녹화 분석에서 버벅임의 주원인이 아카이브·소식의 원본 크기 사진 해독(장당 20–40ms)으로 나와, 아카이브 칸과 소식 카드를 `next/image`로 보이는 크기에 맞춰 내보낸다(`next.config.ts`에 `**.cdninstagram.com` 허용).
